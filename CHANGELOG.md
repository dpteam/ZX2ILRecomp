# Changelog

All notable changes to this project. Format follows

## [0.11.0] — 2026-11-16

The "same pipeline as NesLifter, but for the Spectrum" release. One 4200-line
file became a layered project on .NET 10, with the same guarantees: zero
dependencies, verifiable lifts, CI that runs the result.

### Added

- **Class split.** `Program.cs` is gone; the code lives in `Core/`, `Lifting/`,
  `Compilation/`, `Host/` and `Common/`, one concern per file.
- **.NET 10** (`net10.0-windows`), nullable reference types, `global.json`.
- **Zero NuGet packages.** Roslyn was replaced with the SDK's own
  `dotnet publish`; xUnit with a small assertion harness; the code stays
  dependency-free end to end.
- **Self-test.** `--selftest` builds a synthetic snapshot per container, lifts
  it, packages it and **executes the result headlessly**. Four containers, real
  frame budgets, real exit codes.
- **Screenshot verification.** The generated game takes `--screenshot <path>`,
  and the self-test asserts the resulting frame has a border, paper and ink —
  so a broken ULA decoder fails instead of quietly rendering a blank picture.
- **Unit tests** for CLI parsing, name sanitising, all five loaders, paging,
  opcode lengths, control-flow edges, mnemonics and code generation.
- **GUI.** Native WinForms front end over the same pipeline: folder pickers,
  model and packaging choice, live log, progress bar, cancel.
- **TUI.** Arrow-key menu for consoles that cannot host the window.
- **`analysis.txt`.** Registers, entry point, ROM source, coverage, computed
  jumps, undecoded opcodes and the full disassembly.
- **`--fresh`** to re-lift snapshots that already have output.
- **`--no-sweep`** to skip the linear sweep for a faster, less complete lift.
- **Icon self-capture.** `Game.exe --capture-icon 5` writes
  `<name>.icon.ico`; the next lift embeds it automatically. The wait is baked
  into the build, so a lifted game captures without arguments.
- **Branding.** Vector mark, horizontal logo, multi-resolution `.ico` and a
  GitHub social card, all generated by `tools/Branding`.
- **Documentation.** `ARCHITECTURE.md`, `SNAPSHOTS.md`, `RUNTIME.md`,
  `TROUBLESHOOTING.md`, `ROADMAP.md`, `CONTRIBUTING.md`.
- **CI.** Build in Debug and Release with `-warnaserror`, run the unit tests,
  run the self-test, publish and smoke-test the published binary.

### Fixed

- **Tape entry point.** A `.tap`/`.tzx` was starting at the CODE block's load
  address, which for a commercial release is data. The loader now reads
  `RANDOMIZE USR n` out of the tokenised BASIC loader, in both number encodings
  found in real tapes. This is what makes Manic Miner actually play.
- **Pseudo-ROM never re-enabled interrupts.** The IM 1 handler ended with `RET`
  instead of `EI; RET`, so after the first interrupt `IFF1` stayed clear and the
  game sat in `HALT` forever.
- **`HALT` with interrupts disabled** spun forever instead of reporting. It now
  traps with the address.
- **Frame counting was doubled.** `Halt()` and `CheckInterrupt()` both advanced
  `NextIntT` and both incremented `Frames`.
- **Headless runs overshot the frame budget** (60 requested, 75 delivered)
  because nothing stopped the CPU thread. There is now a hard frame limit.
- **128K ROM was one page cloned into two.** Page 0 and page 1 are different
  ROMs; both are now located and loaded (`128-0.rom` + `128-1.rom`).
- **`ExecCB` was emitted as `ExecCb`** while callers used `ExecCB`. The
  self-test missed it because its synthetic program had no `CB` opcode; it now
  exercises `CB`, `ED`, `DD` and `FD CB`.
- **SZX `RAMP` page number.** The page is at `+0`, not `+1`; the flags byte was
  being read as the bank, so every page landed one bank off.
- **128K `GetFlat` for a 48K snapshot.** Model and paging were compared in a way
  that ignored a snapshot loaded as 48K then switched to 128K.
- **`SP=0x0000` heuristic.** It now uses `0xFF00` instead of `0xFFFF`, which
  overwrote the top word of RAM on the first push.
- **Snapshot names in generated code.** A name with a space produced
  `namespace Lifted.Manic Miner`. Names are now sanitised for the namespace and
  escaped for string literals.
- **Generated array literals.** Multi-row tables were emitted with a leading
  comma on every row but the first, which is a syntax error.
- **`Close()` in the generated form.** The key handler was emitted as `static`,
  so `Close()` bound to nothing.
- **Program class nesting.** The generated `Program` class was never closed,
  leaving the namespace unbalanced.

### Changed

- Logging goes through one facade with pluggable sinks, so the console, the GUI
  and the file all see the same records.
- Progress is a real callback instead of console-only output.
- Snapshot loading reports what it decided (format, version, header size) in
  `analysis.txt` instead of a hex dump on stdout.

### Removed

- The tray icon and the XML state file. A batch of snapshots is cheap enough to
  re-run, and "already lifted" is now a file check, not a state database.
- `CSharpCodeProvider`, which only existed to support .NET Framework.

## [0.10.0] and earlier

Single-file .NET Framework tool: `.z80`/`.sna`/`.tap`/`.szx` loaders, recursive
descent plus linear sweep, Z80 lifter to C#, ULA/beeper/AY runtime, tray icon,
checkpointed state, `CSharpCodeProvider` compilation.
